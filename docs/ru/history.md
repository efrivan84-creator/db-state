# История записи

```js
const page = await state.order.history({ id: 123, limit: 50 }, 'order-history')
const older = await state.order.history({ id: 123, before: page.next, limit: 50 })
```

Ответ: `{ changes, next }`. `changes` использует обычный формат Change;
`next: null` означает конец журнала. Сортировка — по `createdAt`, затем `_id`,
от новых к старым. По умолчанию 50 записей, максимум 200 на страницу.
Страница может быть пустой из-за ограничений полей; продолжать следует по `next`.

Серверный эквивалент — `api.history({ table: 'order', id: 123, req })`.
Метод читает настроенный `logCollection` в той же MongoDB, что и синхронизация:
например, при `prefix: 'admin'` это `admin_log`. Коллекцию журнала не нужно
открывать клиенту как таблицу. История включает собственные действия сессии,
не меняет курсор sync, не применяет старые патчи к текущим записям и не создаёт
новые строки журнала. Возвращается только сохранившаяся история: если журнал
чистится по TTL, удалённые записи восстановить этим методом нельзя.

При каждом запросе проверяется текущий доступ через `beforeRead`/`afterRead`
и права таблицы. Поля ограничены планом чтения и `readChange`; удалённые значения
тоже проецируются. Приложения должны ограничивать чувствительные поля через
`read_fields`, `ctx.fields` или `readChange`, а не только удалять их в `afterRead`.
Отсутствующий документ сам по себе не даёт доступа к его прежним данным.
История не включает `sessionId`.

Серверные хуки `beforeHistory`/`afterHistory` расширяют состав и представление
истории. Перед `beforeHistory` исходный документ уже проверен. Пример переноса:

```js
// hooks/order_archive/beforeHistory.js
export default ctx => {
  ctx.sources = [
    { table: 'order_archive', id: ctx.id },
    { table: 'order', id: ctx.id,
      readAs: { table: 'order_archive', id: ctx.id },
      fields: ['name', 'deadlineAt'] }
  ]
}
```

`sources` задаются только доверенным серверным хуком, клиент не может их
передать. Каждая связанная запись проходит обычное чтение с проверкой прав.
`readAs` явно делегирует доступ существующему документу (например архивному);
`fields` может только сузить разрешённые поля. `afterHistory` получает страницу
в `ctx.result`. Для журнала рекомендуется индекс
`{ table: 1, id: 1, createdAt: -1, _id: -1 }`.

Для обновления открытой ленты используйте существующий `table.onChange()`:
после изменения перечитайте первую страницу. При объединении связанных записей
подпишитесь также на их таблицы. Подписки необходимо снимать при закрытии экрана.
